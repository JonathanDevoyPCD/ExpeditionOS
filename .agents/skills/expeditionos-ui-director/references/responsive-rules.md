# ExpeditionOS Responsive Rules

## Wide desktop

Use space to increase map/context clarity, not to expose every tool simultaneously.

A wide screen may support:

- persistent global sidebar,
- large map canvas,
- contextual side rail,
- compact metric summary,
- secondary planning section below.

## Standard laptop

This is a primary target.

Avoid requiring a very wide screen for the map to remain useful.

If the contextual rail materially compresses the route map:

- reduce rail width,
- make rail collapsible,
- or use a drawer/modal context pattern.

## Tablet

Prefer:

- condensed global navigation,
- map as full-width primary region,
- contextual details below or in a sheet,
- compact route summary,
- horizontally scrollable metrics only if readable and intentional.

Do not recreate the desktop 3-column composition at tablet width.

## Mobile

Prioritize:

1. route identity,
2. critical status/warnings,
3. map,
4. primary action,
5. contextual details,
6. deeper planning modules.

Use bottom sheets/drawers for:

- Copilot,
- place detail,
- route intelligence,
- service detail.

Keep the map tall enough to remain spatially useful.

Avoid:

- tiny side-by-side cards,
- permanent mini sidebars,
- 10px metadata,
- multiple horizontal toolbars,
- interactions dependent on hover.

## Map controls

At all widths:

- keep essential controls reachable,
- avoid overlapping provider attribution,
- avoid covering start/finish or selected geometry,
- keep tap targets comfortable,
- preserve zoom/gesture usability.

## Tables and dense data

On mobile, prefer:

- summary cards,
- labelled rows,
- progressive detail,

over horizontally compressed desktop tables.
