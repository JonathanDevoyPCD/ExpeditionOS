# ExpeditionOS UI Audit Rubric

Use this rubric for AUDIT mode.

## Hierarchy

Ask:

- Is there one obvious focal region?
- Can the user identify the primary task in 3-5 seconds?
- Are primary, secondary, and tertiary actions visually distinct?
- Does the most important information have the strongest visual weight?

Warning signs:

- every panel uses the same treatment,
- multiple equal CTAs,
- headings differ only slightly,
- important warnings look like ordinary metadata.

## Density

Ask:

- Is information grouped efficiently?
- Are simple metrics using too much space?
- Are there unnecessary nested cards?
- Is the page long because content is important, or because every item has its own container?

Warning signs:

- boxes inside boxes,
- giant empty states,
- repeated card headers,
- large padding around tiny values.

## Map prominence

Ask:

- Is the map appropriately dominant for a route-led workflow?
- Can the rider interact with it comfortably?
- Is map width/height reduced by permanent utilities that could be contextual?
- Are overlays clear without covering important geometry?

## Readability

Ask:

- Is body text readable at normal laptop scale?
- Is metadata clearly subordinate but still legible?
- Is contrast strong enough?
- Are labels concise?

## Navigation

Ask:

- Does global navigation stay stable?
- Does the user know whether a control changes workspace, route, tab, context, or state?
- Are deeper workspaces used instead of adding everything to the dashboard?

## Consistency

Ask:

- Do equivalent components look and behave alike?
- Are spacing/radius/type values systematic?
- Are button variants meaningful?

## Discoverability

Ask:

- Can the rider find important tools?
- Does progressive disclosure preserve obvious entry points?
- Are contextual panels labelled clearly?

## Responsiveness

Ask:

- Does layout priority change on smaller screens?
- Is the map still usable?
- Does a side rail become a drawer/sheet instead of crushing the map?
- Are touch targets comfortable?
- Is there horizontal overflow?

## Accessibility

Ask:

- Are controls keyboard accessible?
- Is focus visible?
- Are icons labelled?
- Is colour supplemented by text/iconography?
- Are critical states announced appropriately?

## Task clarity

Ask:

- What is the rider trying to accomplish here?
- What is the next likely action?
- Does the layout actively support that action?
- Is secondary information distracting from it?

## Optional 10-point scoring

Only score if helpful.

- 9-10: excellent
- 7-8: solid with clear improvements possible
- 5-6: usable but hierarchy/density causes friction
- 3-4: confusing or visually overloaded
- 1-2: actively obstructive

Every score below 8 should include a concrete reason.
